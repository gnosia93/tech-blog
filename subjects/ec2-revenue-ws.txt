AWS 파트너/MSP·SI 관점(EC2 사용량 증대 + 후속 프로젝트 수주가 목표)이라고 가정하고 정리했습니다. 다른 포지션(순수 교육사업, ISV)이면 말씀해주세요.

핵심 원칙: 워크샵은 매출이 아니라 파이프라인 장치

워크샵 수강료로 버는 돈은 미미합니다. 실제 매출은 세 경로에서 나옵니다.

1. EC2 사용량 증가 → 리셀 마진 (MSP/리셀러라면 가장 직접적)
2. 워크샵 → Assessment → 유료 PoC → 마이그레이션/구축 계약
3. AWS 자금 회수: MAP(Migration Acceleration Program), POC Funding, Partner Funding Benefits, Immersion Day 크레딧 — 워크샵 실행비를 AWS가 부담하는 구조를 먼저 설계해야 합니다.

가장 먼저 만들 것: 상위 3개

1) VMware → EC2 마이그레이션 워크샵 (1일)
- 오전: VMware 라이선스 비용 시나리오 비교(갱신 vs EC2 vs Dedicated Hosts), Windows/SQL Server 라이선스 최적화(License Included vs BYOL)
- 오후 실습: MGN으로 실제 VM 1대를 EC2로 복제 → 테스트 인스턴스 부팅 → 컷오버 리허설
- 산출물(유료 전환 후크): 참가사 자체 환경 대상 무료 간이 진단 리포트 → 정식 Assessment 유료화

2) GPU 인프라 워크샵 (반일 + 벤치마크 랩)
- 실습: 인스턴스 타입별 학습/추론 처리량 실측, Capacity Blocks·ODCR로 GPU 확보하는 방법, Spot으로 학습 비용 절감, EKS에서 GPU 노드풀 운영
- 이 워크샵의 진짜 가치는 "GPU 못 구해서 못 쓰고 있다"는 고객의 병목을 해결해주는 것 → 즉시 사용량 증가

3) 비용 최적화 워크샵 (반일)
- 실습: Compute Optimizer 기반 rightsizing, Savings Plans vs RI 시뮬레이션, Graviton 호환성 진단 및 실제 전환 벤치마크
- 참가자가 자기 계정 데이터를 들고 오게 설계 → 자연스럽게 계정 접근 → 절감액의 일부를 성과보수(gain share)로 받는 계약 모델 제안 가능

설계 팁

- AWS Workshop Studio 공식 콘텐츠를 베이스로 재활용하세요. 처음부터 만들 필요 없고, 우리 산업/한국 규제 맥락과 실측 데이터를 얹는 것이 차별점입니다.
- 한 세션에 8~15명, 고객사 2~3곳 이하로 제한. 대형 세미나는 리드 품질이 급락합니다.
- GameDay 형식(장애 주입 후 복구 경쟁)이 EC2 운영 주제에서 전환율이 특히 높습니다 — 참가자가 자기 운영 수준의 부족함을 스스로 체감하기 때문입니다.
- KPI를 처음부터 박아두세요: 참가사 수 → Assessment 동의율 → PoC 전환율 → 계약. 만족도 점수는 매출과 무관합니다.

6개월 로드맵

1개월차 비용 최적화 워크샵(제작 난이도 최저, 리드젠 즉시) → 2~3개월차 VMware 마이그레이션(AWS MAP 자금 신청 병행) → 4개월차 GPU 워크샵 → 이후 보안/DR을 산업 특화 버전으로 확장.

어떤 고객군(중견 제조/금융/스타트업/공공)을 주로 보고 계신지 알려주시면, 그중 하나를 골라 워크샵 아젠다·실습 랩 구성·제안서 초안까지 만들어 드리겠습니다.
